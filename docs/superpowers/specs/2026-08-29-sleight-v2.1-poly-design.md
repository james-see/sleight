# Sleight v2.1 Design: Per-Finger Polyphony

**Date:** 2026-08-29
**Status:** Approved design, pending implementation
**Depends on:** v2.0 (`docs/superpowers/specs/2026-08-28-sleight-v2-midi2-design.md`), shipped and working
**Owner:** James Campbell

---

## 1. Summary

v2.1 extends Sleight from monophonic Theremin to a **4-voice polyphonic instrument** where each finger of the right hand plays an independent note with its own per-note pitch bend — leveraging the MPE/UMP multi-channel infrastructure already shipped in v2.0.

Each extended finger maps to a distinct pitch (within the selected scale), retraction releases the note, and continuous finger position drives per-note bend (glide-style). The left hand continues to control shared volume (CC7).

**Key insight:** v2.0's `MIDIEvent.Kind.perNotePitchBendSemitones(note:, Double)` is already per-note — the only missing pieces are (a) a `ChannelAllocator` so multiple simultaneous notes land on distinct MPE channels, and (b) a new instrument that emits multiple notes per frame.

---

## 2. Background: v2.0 architecture in place

- `UMPEncoder` has `MIDIMode { ump, mpe, legacy }` and `encode(_ event: MIDIEvent) -> [UInt32]`.
- For UMP: per-note management is by note number (32-bit values, group 0, channel 0).
- For MPE: note events go on channel nibble 1 ("channel 2"), CC on nibble 0. **But all notes share the same channel** — monophonic.
- `MIDISource.send(_:)` calls `encoder.encode($0)` per event with no channel state passed.
- `Theremin` emits at most one `noteOn`/`noteOff` and one `perNotePitchBendSemitones` per frame.

---

## 3. What stays unchanged

- Pipeline architecture (Capture → Track → Filter → Map → Output).
- CoreMIDI virtual source (`MIDISource.shared`), `MIDIReceivedEventList` send path.
- `MIDIEvent.Kind` enum — **no new cases** (reuses existing `.noteOn`, `.noteOff`, `.perNotePitchBendSemitones`, `.cc`).
- Settings persistence pattern (`@Published` + Combine sink to UserDefaults).
- Release workflow (tag-triggered CI on `v*`, same as v2.0).
- `SleightController` structure (owns pipeline + instrument + settings).

## 4. Design

### 4.1 Channel Allocator (`MIDI/ChannelAllocator.swift`, new)

A small, stateful struct that maps MIDI note numbers → MPE channel indices. Owned by `MIDISource`.

```swift
public enum ChannelMode {
    case ump          // MIDI 2.0: all on group 0, channel 0 (per-note by note number)
    case mpe(maxVoices: Int)  // MIDI 1.1 MPE: channels 2..(2+maxVoices-1), CC on ch 1
    case legacy       // MIDI 1.1: monophonic, channel 1 only (last-note priority)
}

public struct ChannelAllocator {
    public init(mode: ChannelMode)
    public mutating func channel(forNote note: UInt8) -> UInt8?   // returns assigned channel, or nil if note off
    public mutating func noteOn(_ note: UInt8) -> UInt8          // allocate channel (steal oldest if full)
    public mutating func noteOff(_ note: UInt8)                  // release channel for this note
    public mutating func reset()                                  // all notes off, reclaim all
}
```

**Channel allocation strategy (MPE):**
- Channels 2–5 (nibbles 1–4) for 4-note polyphony, channel 1 (nibble 0) for global CC.
- First available channel on note-on.
- When all 4 in use: steal the **oldest** (first-allocated) voice — standard MPE poly-keyboard behavior.
- Note-off reclaims the slot immediately (no release phase / no retrigger).
- The allocator tracks `note number → channel` so per-note bend messages route to the right channel.

**UMP mode:** Always channel 0 — UMP 2.0 manages per-note state by note number in the 64-bit message structure. Allocator is a no-op pass-through.

**Legacy mode:** Always channel 0 (monophonic, last-note priority). Per-note bend collapses to channel bend (v1 behavior). No polyphony.

### 4.2 `MIDIEvent` — channel field (minimal extension)

The current `MIDIEvent.Kind` cases carry note numbers but no channel. For MPE polyphony, the encoder needs to know which channel each note lives on. Two options:

**Option A (chosen):** Add an optional channel to `noteOn`/`noteOff`/`perNotePitchBendSemitones` — but with defaults so existing call sites don't change:

```swift
public enum Kind: Equatable {
    case noteOn(note: UInt8, velocity: Double, channel: UInt8 = 0)
    case noteOff(note: UInt8, channel: UInt8 = 0)
    case perNotePitchBendSemitones(note: UInt8, Double, channel: UInt8 = 0)
    case cc(UInt8, UInt8)  // unchanged — global, channel 0
}
```

The default `channel: 0` means all existing Theremin code, tests, and the UMP path work unchanged. MPE poly instruments set the channel from `ChannelAllocator`.

**Why not a separate `PolyEvent` type?** Keeps a single event stream through `MIDISource.send(_:)` — no protocol bifurcation, no parallel code path. The channel is metadata on the same event.

### 4.3 `UMPEncoder` — channel-aware encoding

The encoder gains an internal `channel(for:)` resolution step:

```swift
// UMP mode: ignore channel (per-note by note number)
// MPE mode: use the channel from the event (nibble 1 = ch 2 for poly)
// Legacy mode: use channel 0
```

The public `encode(_:)` signature stays `[UInt32]` — channel comes from the event. Test vectors get MPE channel 2/3/4/5 variants.

### 4.4 `MIDISource` — allocator integration

```swift
private var allocator: ChannelAllocator  // mode-aware

public func send(_ events: [MIDIEvent]) {
    guard source != 0, !events.isEmpty else { return }
    var translated: [MIDIEvent] = []
    for e in events {
        switch e.kind {
        case .noteOn(let note, let vel, _):
            let ch = allocator.noteOn(note)
            translated.append(MIDIEvent(kind: .noteOn(note: note, velocity: vel, channel: ch), timestamp: e.timestamp))
        case .noteOff(let note, _):
            allocator.noteOff(note)
            // channel from allocator (or 0 if not tracked)
            let ch = allocator.channel(forNote: note) ?? 0
            translated.append(MIDIEvent(kind: .noteOff(note: note, channel: ch), timestamp: e.timestamp))
        case .perNotePitchBendSemitones(let note, let semis, _):
            let ch = allocator.channel(forNote: note) ?? 0
            translated.append(MIDIEvent(kind: .perNotePitchBendSemitones(note: note, semis, channel: ch), timestamp: e.timestamp))
        case .cc:
            translated.append(e)  // global, channel 0
        }
    }
    let chunks = translated.map { encoder.encode($0) }
    transmit(chunks)
}
```

**Important:** The allocator is reset on mode change (`configure`). When switching from UMP (monophonic) to MPE (poly), all notes should be released first to avoid channel drift.

### 4.5 New instrument: `PolyPads` (`Instruments/PolyPads.swift`)

A multi-finger pad/controller instrument. Right hand fingers become independent voices:

```swift
public final class PolyPads: Instrument {
    var id: String { "poly-pads" }
    var displayName: String { "Poly Pads" }
    // Configuration
    var voiceCount: Int = 4        // 2–4 fingers
    var scale: Scale = .minorPentatonic
    var root: Int = 60
    var octaves: Double = 2
    var pitchBand: ClosedRange<Double> = 0.55...0.95  // right-hand horizontal band
    // State (per-finger)
    private var voiceNotes: [Int: UInt8] = [:]  // fingerIndex → note number
    private var currentNotes: Set<UInt8> = []   // sounding notes
}
```

**Finger mapping:**
- Fingers used: `index(8)`, `middle(12)`, `ring(16)`, `little(20)` (tip landmarks)
- For each finger, the **Y position** (vertical) maps to pitch: top of pitch band = low note, bottom = high note (like a keyboard rotated 90°). Within the pitch band, quantize to the nearest scale tone.
- **Gate**: finger extension. Use the angle at the MCP joint (e.g., index PIP at landmark 6, DIP at 7, tip at 8) — if the finger is extended (angle > threshold), note is on; if flexed (angle < threshold), note is off.
- **Per-note bend**: raw finger Y (before quantization) drives per-note bend from the held note — same glide math as Theremin, but per-finger.
- **Velocity**: how far extended the finger is (full extension = velocity 1.0, partial = softer).
- **Left hand**: still controls shared volume (CC7), identical to Theremin.

**Why Y = pitch (not X)?** Vertical finger position gives a natural keyboard-like layout — higher finger = higher note. X stays available for timbre/vibrato width per voice.

**Note assignment:** Each finger gets a **fixed voice slot** (finger 0 → channel 2, finger 1 → channel 3, etc.) — the allocator maps the note number to the channel, so as long as each finger emits a distinct note, they land on distinct channels. If two fingers happen to quantize to the same note (same scale degree, different octaves won't happen with 4 fingers in 2 octaves), the second one is a duplicate note-on on the same note — the allocator handles this (already-on note → no re-trigger, but bend continues).

Actually, to keep it simpler and more predictable: assign voices by finger position, not by note number collision. Finger 0 always = voice 1 (channel 2), finger 1 = voice 2 (channel 3), etc. The channel allocator tracks by voice slot, not note number.

**Revised allocator interface:**
```swift
// Voice-based allocation instead of note-based
public mutating func noteOn(voice: Int) -> UInt8    // voice 0..3 → channel 2..5
public mutating func noteOff(voice: Int)
```

This is simpler: each finger is a voice, each voice has a fixed channel. The instrument owns the voice→finger mapping.

### 4.5 Settings + UI

- `AppSettings.voiceCount: Int` (2–4, persisted)
- `AppSettings.instrument: String` ("theremin" | "poly-pads")
- `SleightController.applySettings()`: instantiates the right instrument, configures `MIDISource` with `ChannelMode.mpe(maxVoices: voiceCount)`.
- Settings sheet: "Instrument" picker + "Voices" stepper (only visible when poly-pads selected).
- Pipeline: `instrument` becomes settable from controller (currently hardcoded in `Pipeline.init`).

### 4.6 Overlay

`OverlayState` gains:
- `activeVoices: [Int: Double]?` — finger index → pitch for visual cursor per voice
- `noteNames: [Int: String]?` — per-voice note names

`OverlayView` draws a small cursor + note name per active voice in the pitch band.

## 7. Risks & Mitigations

- **MPE channel exhaustion**: 4 fingers × 14 channels = plenty, but if the user switches instruments without note-off, stale notes on freed channels could misbehave. Mitigation: `configure()` calls `allocator.reset()` which sends all-notes-off on the previous mode.
- **Finger detection jitter**: Extension angle can oscillate at the threshold. Mitigation: reuse `PinchDetector`'s hysteresis pattern — per-finger on/off thresholds with 10% hysteresis.
- **Left-hand absence**: If the left hand is gone, hold last volume (already in Theremin, copy the pattern).
- **Same note, different fingers**: Two fingers quantizing to the same scale tone. Mitigation: voice slots are fixed per finger (finger 0 → voice 1), so duplicates just share a channel — the second note-on is a no-op, bend continues from whichever finger is active. Documented as expected behavior.
- **Overdub vs live**: Vision latency (~3–8ms) is fine for 4 fingers — no additional per-finger latency budget beyond what v2 already handles.
